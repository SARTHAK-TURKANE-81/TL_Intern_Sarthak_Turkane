MICROCONTROLLER & IoT PLATFORM

ESP32 & Firebase Integration

ESP32 is a powerful, low-cost microcontroller developed by Espressif Systems. It combines dual-core processing with built-in Wi-Fi and Bluetooth, making it one of the most widely used platforms for IoT applications. This week, the ESP32's full pinout and internal architecture were studied in detail — understanding which pins carry which functions before wiring any circuit.

ESP32 Pin Architecture — Studied This Week

Processor

Dual-Core Xtensa LX6 running up to 240 MHz — handles both Wi-Fi stack and user application simultaneously.

Memory

520 KB SRAM with external flash support. Enough for sensor buffering and Firebase communication tasks.

Wireless

Integrated Wi-Fi (802.11 b/g/n) and Bluetooth 4.2/BLE — the key feature that enables Firebase cloud connectivity.

GPIO & Peripherals

34 GPIO pins with 18 ADC channels, 2 DAC channels, PWM, I2C, SPI, UART — each studied for its specific role.

Power

3.3V operating voltage with Deep Sleep mode for battery deployments. USB powered during lab sessions.

Development Environment

Arduino IDE was used for all programming during the week. Libraries: FirebaseESP32, DHT sensor, Servo.

Learning Outcome:
Understanding the ESP32's pin map before any circuit work prevented wiring errors. The deep-dive into its architecture clarified why it is the go-to microcontroller for IoT builds — processing power plus wireless in a single affordable chip.

ACTUATOR — PRECISE POSITION CONTROL

Servo Motors & Actuators

Servo motors were studied and used hands-on this week. Unlike a regular DC motor that simply spins, a servo motor accepts a PWM (Pulse Width Modulation) signal and rotates to a precise angular position — making it essential for any application where controlled movement matters, such as robotic arms, camera gimbals, or automated doors.

How a Servo Motor Works

Input Signal

A PWM signal (typically 50 Hz) with pulse width between 1 ms and 2 ms determines the target angle.

  • 1 ms pulse → 0°
  • 1.5 ms pulse → 90°
  • 2 ms pulse → 180°

Internal Components

A servo contains a DC motor, a gear train, a position sensor (potentiometer), and a control circuit — all in one compact unit.

Closed-Loop Control

The internal pot continuously reports actual angle. The control circuit adjusts motor drive until actual position matches target.

Servo with ESP32 — Arduino Code Pattern

#include <ESP32Servo.h>

Servo myServo;

myServo.attach(18); // GPIO 18

myServo.write(90); // Rotate to 90 degrees

myServo.write(0); // Rotate to 0 degrees

Where Servo Motors Are Used

Robotics

Robotic arms use multiple servo joints to achieve multi-axis precise movement and manipulation.

Drones & Gimbals

Camera stabilisation gimbals use servos to compensate for movement and maintain level framing.

RC & Vehicles

Steering control in RC cars and model aircraft uses servos for accurate direction response.

Smart Automation

Automated door locks, valve controllers, and conveyor position systems rely on servo precision.

Learning Outcome:
Servo motors demonstrate how a feedback loop — even a simple internal one — transforms a dumb spinning motor into a precision positioning tool. This directly parallels how PID control loops are used in larger systems.

DISTRIBUTED COMPUTING MODEL

Edge Computing

Edge Computing is a distributed computing model where data processing occurs close to the data source rather than a centralized cloud server. For latency-sensitive and privacy-critical applications, edge computing provides significant advantages over traditional cloud-based approaches.

Why Edge Computing?

Faster Response

Processing at the source eliminates round-trip cloud latency, enabling near-instant real-time decisions.

Reduced Bandwidth

Only results or processed summaries are transmitted, drastically reducing network consumption.

Improved Privacy

Sensitive data such as medical images never leaves the local device, ensuring patient data security.

Real-Time Decision Making

Critical applications like autonomous vehicles or medical diagnostics require millisecond-level responses.

FEEDBACK & REGULATION SYSTEMS

Control Systems — P, PI & PID

Control systems regulate machine behavior automatically by continuously monitoring output and adjusting inputs to minimize error. Three controller types were studied: P, PI, and PID, each offering increasing levels of accuracy and stability.

P — Proportional

The simplest controller — output is directly proportional to the current error. If the error is large, the correction is large; if small, the correction is small. Easy to tune and fast to respond, but it cannot fully eliminate error on its own. A residual offset always remains at steady state.

Best for: Basic speed control, simple loops where a small offset is acceptable.

PI — Proportional + Integral

Adds an integral term that accumulates past error over time. Even a small persistent offset will build up in the integrator and eventually drive the output to zero error — eliminating the steady-state limitation of the P controller. Slightly slower to settle but far more accurate.

Best for: Temperature regulation, motor speed control, flow systems.

PID — Proportional + Integral + Derivative

The industry standard. The derivative term predicts future error by measuring the rate of change — damping overshoot and oscillation before they happen. Together, all three terms deliver fast response, zero steady-state error, and excellent stability even in dynamic systems.

Best for: Robotics, drones, CNC machines, industrial automation.

Learning Outcome:
PID controllers are the industry standard in precision automation systems. Understanding their behavior is critical for designing stable, responsive control loops in robotics and embedded systems projects.

PERCEPTION & MEASUREMENT

Sensors Documentation

A sensor converts physical phenomena into measurable electrical signals. Sensors are categorized as Active (require external power) or Passive (respond to environmental changes without external energy input). This week, the DHT11 temperature & humidity sensor was used live to stream data to Firebase.

Active Sensors

Ultrasonic Sensor

Working Principle: Uses sound waves to measure distance by calculating time-of-flight of reflected pulses.

Range: 2 cm – 400 cm

  • Obstacle Detection
  • Robotics Navigation
  • Parking Assistance Systems

LiDAR Sensor

Working Principle: Uses laser pulses to calculate precise distances and create 3D environment maps.

Range: Up to several hundred meters

  • Autonomous Vehicles
  • 3D Mapping Systems
  • Advanced Robotics
Passive Sensors

LDR (Light Dependent Resistor)

Working Principle: Resistance changes proportionally with ambient light intensity.

  • Automatic Street Lighting
  • Light Monitoring Systems
  • Display Brightness Control

Thermistor / DHT11

Working Principle: Resistance changes with temperature; DHT11 additionally gives humidity readings digitally.

  • Temperature Monitoring (used this week)
  • Medical Diagnostic Devices
  • Industrial Thermal Control

MOTION & MECHANICAL ACTUATION

Actuators & Motors

Actuators translate electrical control signals into physical mechanical action. Five major motor types were studied, each with distinct operating principles and application suitability. The Servo Motor was used hands-on this week with the ESP32.

Induction Motor (AC)

Operates on AC supply through electromagnetic induction. Widely used in industrial machinery and high-power applications.

DC Motor

Powered by direct current with straightforward speed control via voltage adjustment. Common in robotics and consumer devices.

Stepper Motor

Rotates in precise discrete steps, providing positional accuracy without feedback. Ideal for CNC machines and 3D printers.

BLDC Motor

Brushless design eliminates mechanical wear, delivering high efficiency and reliability. Used in drones and electric vehicles.

Servo Motor

Closed-loop control with position feedback delivers extremely precise angular control. Interfaced with ESP32 via PWM during lab session.

SWITCHING & POWER CONTROL

MOSFET & Relay

MOSFETs and Relays are the two primary technologies used for switching and power control in embedded and IoT systems, each suited to different voltage, speed, and isolation requirements.

MOSFET — Metal Oxide Semiconductor Field Effect Transistor

Terminals & Types

  • Gate — Control input terminal
  • Drain — Output current terminal
  • Source — Reference terminal
  • N-Channel: Higher efficiency, widely used
  • P-Channel: High-side switching

Advantages & Applications

  • High Switching Speed
  • Low Power Loss
  • Motor Drivers & H-Bridge Circuits
  • Power Supply Regulation
  • Battery Management Systems
  • Robotics Drive Circuits
Relay — Electrically Operated Switch

Key Advantages

  • Complete electrical isolation between control and load circuits
  • Controls high voltage loads using low voltage microcontroller signals
  • Simple to interface with Arduino and ESP32

Applications

  • Home Automation Systems
  • Industrial Equipment Control
  • Smart Appliance Switching
  • AC Load Control via Microcontroller
Learning Outcome:
MOSFETs are preferred for high-speed, low-loss switching in DC circuits, while Relays are used when electrical isolation is critical or when switching AC mains loads from low-voltage controller circuits.

EDGE AI PLATFORM — HANDS-ON

Edge Impulse Platform

Edge Impulse is an open-source, end-to-end machine learning platform designed specifically for building and deploying ML models on embedded devices and microcontrollers. It enables developers to train image classification, audio recognition, and sensor anomaly detection models — entirely through a browser-based interface — without writing training code.

End-to-End Pipeline on Edge Impulse
1

Data Collection

Connect a device (Arduino, Raspberry Pi, phone) and collect labelled sensor data or images directly through the Edge Impulse dashboard. Data is automatically organised into labelled classes.

2

Create Impulse (Feature Extraction)

Design the signal processing pipeline — choose what features to extract from raw data (e.g. spectral analysis for audio, image normalization for vision tasks).

3

Model Training — No Code Required

Select a neural network architecture (or let Edge Impulse's AutoML choose), then click Train. The platform handles dataset splitting, training epochs, and accuracy validation automatically.

4

Model Testing & Validation

Test the trained model against a held-out test dataset. Live classification from a connected device can be streamed directly to the dashboard to verify accuracy in real conditions.

5

Deployment on Embedded Device

Export the trained model as an Arduino library, C++ source, or firmware binary. Flash it onto the target device — it runs locally with no internet connection required.

What Was Explored This Week

Labels & Classes

Understood how labelled data classes are created — each class represents one category the model learns to recognise (e.g. "cat", "dog", or "normal", "anomaly").

No-Code Training

Explored the Edge Impulse studio UI to understand how model training happens without writing a single line of Python or TensorFlow code.

Open Source Projects

Explored public Edge Impulse projects — pre-built models for gesture recognition, keyword spotting, and predictive maintenance that can be cloned and deployed directly.

COMPUTER VISION LIBRARY

OpenCV & Computer Vision Basics

OpenCV (Open Source Computer Vision Library) is one of the most widely used libraries for real-time computer vision tasks. It was introduced this week as the vision backbone that powers many Edge AI applications — including image classification, object detection, and the kind of skin image processing needed in the ongoing Skin Cancer Detection project.

What OpenCV Does

Image Processing

Reading, resizing, colour space conversion (BGR → RGB → Grayscale), and applying filters to prepare images for ML models.

Object Detection

Real-time detection of objects in a video stream using pre-trained classifiers and deep learning models like YOLO.

Feature Extraction

Detecting edges, contours, and keypoints in images — the same pre-processing steps used before feeding images into neural networks.

Camera Integration

Direct integration with USB cameras and Raspberry Pi camera modules to capture and process frames in real time.

CLOUD IoT INTEGRATION

ESP32 & Firebase IoT Architecture

Firebase is a cloud-based platform by Google that enables real-time data synchronization between multiple devices. When combined with ESP32, it creates a powerful bi-directional IoT communication channel for remote monitoring and control applications — exactly what was built hands-on this week.

Write & Read Operations

ESP32 → Firebase (Write)

ESP32 sends data to the Firebase Realtime Database for cloud storage and multi-device access.

  • Temperature & Humidity Readings
  • Device Status Updates
  • Sensor Event Logs

Firebase → ESP32 (Read)

ESP32 receives commands and configuration from Firebase, enabling remote device control.

  • LED ON/OFF Commands
  • Servo Motor Angle Commands
  • Remote Device Settings
System Architecture

DHT Sensor → ESP32 → Firebase Realtime DB → Web Dashboard (live temp)

Web Dashboard Button → Firebase Realtime DB → ESP32 → LED ON/OFF

ESP32 Device 1 ↔ Firebase Realtime DB ↔ ESP32 Device 2

Advantages of ESP32 + Firebase

Real-Time Sync

Data changes propagate instantly across all connected devices and dashboards without polling.

Remote Monitoring

View live sensor data and device status from anywhere in the world via a mobile or web interface.

Multi-Device Communication

Multiple ESP32 devices can read and write to shared data nodes, enabling coordinated IoT systems.

Cloud Storage

Historical sensor data is persisted in the cloud for trend analysis, logging, and remote diagnostics.

Learning Outcome:
The ESP32–Firebase integration provides a complete IoT communication pipeline, enabling both real-time remote monitoring and bidirectional device control — essential for connected healthcare and smart automation systems.
